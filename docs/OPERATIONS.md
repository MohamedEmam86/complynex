# Operations (Phase 6: P6-4 settings and rebuild, P6-7 monitoring)

## Settings (P6-4)
* Every setting the code reads from the environment is listed in `.env.example`
  (81 settings, 14 marked `[secret]`), generated by `scripts/env_example.py --write`.
  Re-run it after adding a setting. The file holds names only, never values.
* `scripts/env_example.py --check /var/www/complynex/.env` prints which settings the code reads
  that the `.env` does not set (the code default applies) and the reverse. Names only.
* Check of 1 Nov 2026 on production: the `.env` sets 29 names; 54 settings run on their code
  default; `ELASTICSEARCH_URL` and `EKYC_ENCRYPTION_KEY_V1` are set but not read by name (the
  eKYC key is read by a versioned name pattern; `ELASTICSEARCH_URL` is unused).
* **Gap:** `ENCRYPTION_KEY` (field encryption of customer data, `data_protection/encryption_service.py`)
  is not set, so the key is derived from `SECRET_KEY`. Rotating `SECRET_KEY` would make that data
  unreadable. Before any key rotation: set `ENCRYPTION_KEY` to the derived value first (needs a
  one-off script; never paste keys in chat), then rotate `SECRET_KEY`.

## Server monitoring (P6-7)
* `scripts/ops_monitor.py`, every 5 minutes (`complynex-ops-monitor.timer`), read-only.
* Checks: disk (`/`, `/var/backups`), memory available, CPU load per core, services
  (complynex, postgresql, elasticsearch, redis, nginx, eKYC worker, event dispatcher), key timers,
  failed ComplyNex units, last backup run, PostgreSQL connections vs max, Elasticsearch health,
  queues (open screening hits, running bulk jobs, pending clearances), list freshness.
* Levels ok / warn / crit / unknown. Thresholds: `OPS_*` settings (`.env.example`), e.g. disk
  80/90 %, memory 1500/600 MB available, load 1.5/3.0 per core, backup 30/54 h, PG 70/90 %.
* Output: `logs/ops_status.json` + 2 days of changes in `logs/ops_history.jsonl`; admin page
  **/admin/server-status** (also flags the monitor itself when it is more than 15 minutes late).
* Alerts: a check turning warn/crit (or changing level) notifies every active admin in the app
  and e-mails `OPS_ALERT_EMAIL` if set; repeated every `OPS_REALERT_HOURS` (6) while it lasts;
  recovery announced once; `unknown` never alerts.
* Install: copy `deploy/systemd/complynex-ops-monitor.{service,timer}` to `/etc/systemd/system`,
  `systemctl daemon-reload && systemctl enable --now complynex-ops-monitor.timer`.
* First reading (1 Nov 2026): all checks ok except "failed ComplyNex units": the
  `complynex-sanctions-update` run of 1 Nov (EMLCU blocked, fixed the same morning) and the old
  `cx-os-classify` one-off; `systemctl reset-failed` clears them.
